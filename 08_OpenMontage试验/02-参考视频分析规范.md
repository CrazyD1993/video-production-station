# 02 参考视频分析规范

## 三种输入模式

1. `profile_url`：只分析公开账号简介、帖子列表、标题、封面、页面可见互动与选题分布。账号级分析不等于视频级拆解。
2. `post_urls`：用户提供 3 条具体帖子链接。只有匿名公开访问确实取得可播放视频，才运行镜头级拆解。
3. `local_files`：公开帖子无法读取视频时的后备方案。用户将 `REF01.mp4`、`REF02.mp4`、`REF03.mp4` 放入本地忽略目录。

不得要求账号密码、Cookie、浏览器登录状态或验证码绕过。

## 独立状态

```yaml
account_profile_analysis:
  status: pending | completed | blocked
video_deep_analysis:
  status: pending | completed | blocked
  blocked_reason: null
```

没有 MP4 时仍可完成账号定位、标题/封面模式、选题类型和公开互动差异；只有镜头、旁白、字幕、声音和素材占比必须依赖可播放视频。

## 允许提取

- transcript 的信息段落与时长分布；
- 0—3 秒 hook 类型；
- pacing、场景数量、平均镜头时长；
- keyframes 的构图功能，不复制画面内容；
- 真实素材、AI 画面、结构示意、字幕的比例；
- 字幕密度、声音节拍、封面结构；
- retention mechanics：异常、延迟解释、反转、可复述结论；
- 评论区争议来自事实分歧、措辞误解还是视觉误导。

## 禁止复用

- 原视频画面、音轨、旁白、标题和文案；
- 原人物、角色、Logo、视觉资产；
- 高度相似的镜头顺序、转场组合和封面构图；
- 未核实的因果、灾难后果或实验结果。

## 标准输出

```text
参考视频基本信息：来源、时长、画幅、授权/分析状态
视频级拆解状态：已完成 / 未完成（原因）
保留的结构：hook 类型、信息推进节拍、场景密度、结尾功能
改变的内容：题材、事实论证、视觉主体、镜头顺序、旁白表达
不可复用资产：逐项列明
本项目适配：5—7 镜头、35—45 秒、9:16
风险：相似度、事实、素材授权、平台规则
```

真实拆解完成后必须同时生成：

- `001-飞机舷窗小孔/参考视频拆解.md`
- `001-飞机舷窗小孔/reference-profile.yaml`

每条参考视频至少记录：总时长、镜头数、平均/中位镜头时长、前 1/3/5 秒事件、开头主体比例、AI 视频/真实素材/静态图/解释动画占比、字幕位置与密度、每分钟旁白字数、音效与 BGM 进入节点、视觉变化频率、反转时间、结论时间、评论或关注驱动机制。

可播放视频未取得时不得提前创建带有推测统计值的上述两个输出文件。

## 本试点的文字模型

保留：熟悉物件 + 不起眼异常 + 延迟揭示其功能 + 可复述结论。  
改变：不复制任何竞品标题/镜头；第一版只用舷窗微距、真实分层结构、客舱侧与特定夹层连通、典型承压层建立原创叙事。
争议控制：不说“堵住立刻爆裂”，不把结构示意伪装成真实事故。
