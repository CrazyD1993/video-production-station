```text
video-production-station（私有内容中枢）
  选题 / 事实 / 创意 / 脚本 / 审批 / 素材台账 / 发布复盘
                  │

  Backlot / Provider 路由 / 关键帧与视频资产 / 字幕声音 / 合成审核
                  │
                  │ 仅回写状态、成本、选中 take、授权信息
                  ▼

```

## 交接数据流

1. 主仓库完成事实核查、创意、脚本和 5—7 镜头故事板。
2. 用户批准一个创意方向和三个关键帧各一个候选。
3. 将 `03-生产清单模板.yaml` 实例化到 OpenMontage project workspace。
4. OpenMontage 初始化 Backlot，并写入 proposal/script/scene-plan checkpoint。
5. 若为模式 A，`video_selector` 使用 `preferred_provider=seedance`，优先 I2V/RTV；若为模式 B，输出手动交接包。
6. 用户把手动生成文件放入 `incoming/seedance/`，不提交 Git。
7. OpenMontage 读取、探测、审核镜头，只把选中 take、成本和授权状态回写主仓库。
8. 所有镜头批准后才允许合成；本轮停在第 2 步。

## 安全规则

- `.env` 只存在于 OpenMontage 本地目录；任何检查只输出“已配置/未配置”。
- 禁止在 Markdown、YAML、shell history、Git diff 或终端日志出现密钥值。
- 禁止抓取或提交小红书竞品原视频；只有用户明确提供本地文件或可访问链接时才做 reference-video 分析。
- 下载媒体、生成视频、缓存、代理文件、未授权素材均不进入主仓库。
- 主仓库只保存可审计的小文本和自有提示词。

## 故障降级

- Provider 不可用：切换手动 Seedance，不阻塞方案与审批。
- Backlot UI 不可用：继续写 checkpoint 和 Markdown；UI 是观察层，不是数据源。
- HyperFrames 不可用：本试点不依赖它；后续只在确有动效需求时复查。
- 参考视频缺失：只使用现有竞品文字模型，不写“已完成视频级拆解”。
- 事实来源不足：删除或弱化断言，不用视觉戏剧性替代事实。
