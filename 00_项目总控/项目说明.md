# 视频制作站项目说明

## 项目目标

建立一个由 AI 导演驱动的小红书科普短视频生产系统：产品经理 Agent 统筹选题、调研、脚本、导演设计、动态分镜、声音、剪辑、审片、发布和复盘。

用户只参与关键审核与确认，尽量减少日常执行工作；自动化不能以牺牲观看体验为代价。

## 当前生产架构（OpenMontage 试验）

- 本仓库继续作为内容与运营中枢，管理账号定位、竞品拆解、选题、事实核查、发布计划、数据复盘和项目状态。
- 视频生产执行层评估同级独立工具 OpenMontage，不将其 AGPL 源码复制进本仓库。
- 第 003 条 R1/R2 保留为自研 Remotion 技术验证历史，不再继续制作完整版。
- 首个试点为 `001 飞机窗户上的小孔，为什么要留着？`，先经过故事板、关键帧、Seedance 镜头三道人工门禁。

## 素材使用模式

- 项目默认处于“个人本地学习”模式，完整规则见 `00_项目总控/素材收集与本地学习规则.md`。
- 在本地学习模式下，公开可访问且权利状态未知的素材可以进入本地候选池、竞品分析、素材板、测试剪辑和非公开审核样片；授权状态不阻塞搜索、下载和内部试剪。
- 素材应优先寻找无水印、无烧录字幕、无二次搬运标识的原始版本；不得主动删除或改变已有权利管理信息，也不得突破付费、DRM 或账号访问控制。
- 当任务转为公开发布、商用、广告投放或对外分发时，再对实际进入交付物的素材逐项核验；这一门禁不追溯限制个人本地搜集。

## V2 制作原则

```text
观看兴趣 > 视觉表达 > 故事推进 > 信息价值 > 自动化效率
```

- 前 3 秒必须有冲突、反差、动作或强主体，不能只用氛围空镜。
- 约每 3 秒发生一次镜头、动作、构图或信息变化。
- 每条至少有一个视觉证据：实验、对比、动态模拟、结构拆解或地图变化。
- 画面比旁白多提供一层信息；静态信息卡只用于总结，累计不超过时长的 15%。
- 成片进入发布前，必须通过导演 Agent 和冷观众审片 Agent 两道门禁。

## 当前账号方向

先以「生活风险 + 猎奇科学 + 极端假设」作为起号方向。

核心内容不是严肃课堂式科普，而是把知识包装成普通用户愿意点击、收藏、评论和转发的短视频内容。

## 初始内容模型

参考竞品「天赐科普」的可复刻模型：

```text
熟悉事物
+ 陌生后果
+ 强视觉主体
+ 数字 / 实验 / 历史背书
+ 生活落点
+ 评论区自然争议
```

## 内容边界

优先做：

- 生活里的隐藏风险：美甲、食物、厨房、夜市、紫外线、自酿酒、寄生虫。
- 灾害与应急：台风、高温、热射病、暴雨、极端气候。
- 动物与古生物：动物战斗力、史前巨兽、反常识生物。
- 假设实验：把熟悉动物或物品放进极端历史/史前/自然环境。
- 历史奇案和科学发现：医学实验、考古故事、疾病发现史。

谨慎做：

- 医疗诊断、用药建议、疾病恐吓。
- 过度夸张的灾害预警。
- 没有来源支撑的科学断言。
- 直接复刻竞品标题、封面、文案和视频结构。

## 用户确认节点

用户只需要参与 4 个关键节点：

1. 账号定位确认
2. 选题确认
3. 脚本 / 分镜确认
4. 发布前确认

其余任务由产品经理 Agent 分配给子 Agent 自动推进。

## 版本与备份

- 项目以 GitHub 私有仓库作为版本备份和协作入口。
- 每次新增或更新有效项目资料后，Agent 都应执行：检查变更、提交、推送。
- 不提交账号密码、Cookie、第三方原始视频、图片、音频、未核验素材和个人隐私；这些素材可以按本地学习规则保存在本机，但不得进入 GitHub。
- 首次上传前，需确保 GitHub CLI 账号授权有效。

## 成功标准

短期目标：

- 先跑通 1 条内容完整生产链路。
- 形成可复用的选题、脚本、分镜、封面、复盘模板。
- 30 天内完成至少 30 条内容的生产与测试。

中期目标：

- 找出 2-3 个稳定高互动栏目。
- 建立每周复盘机制。
- 让产品经理 Agent 能根据数据自动提出加码或放弃建议。
